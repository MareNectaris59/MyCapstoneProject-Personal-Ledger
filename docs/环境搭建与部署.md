# 环境搭建与部署

本文档说明如何把项目拷到 U 盘、换一台电脑（已装好 MySQL / JDK / Maven）后直接跑起来。

> **一句话**：真正需要拷的只有约 **1 MB 源码与文档**。
> `node_modules`（180 MB）和 `target`（52 MB）都**不必拷** —— 前端产物已包含在后端代码里。

---

## 一、拷什么、不拷什么

| 目录 / 文件 | 大小 | 是否要拷 | 原因 |
| --- | --- | --- | --- |
| `backend/src/` | 0.4 MB | ✅ 必须 | 后端源码 + Flyway 迁移脚本 + **编译好的前端产物** |
| `frontend/src/` | 0.1 MB | ✅ 必须 | 前端源码（只在要改前端时才用） |
| `docs/` `db/` | 0.4 MB | ✅ 必须 | 设计文档、数据库导出 |
| `backend/pom.xml` | 8 KB | ✅ 必须 | 依赖声明 |
| `*.ps1`、`README.md` | 20 KB | ✅ 必须 | 初始化与测试脚本 |
| `frontend/package.json` | 1 KB | ✅ 必须 | 前端依赖声明 |
| `backend/target/` | 52 MB | ❌ 不要 | 构建产物，`mvn package` 会重建 |
| `frontend/node_modules/` | 181 MB | ❌ 不要 | 含平台相关二进制，换机器必然失效；**且运行不需要它** |
| `frontend/dist/` | 0.1 MB | ❌ 不要 | 已复制到 `backend/src/main/resources/static/` |
| `.idea/` | — | ❌ 不要 | 含机器相关配置，IDEA 会自己重建 |
| `.skills/` | 大 | ❌ 不要 | 第三方技能包，与项目运行无关 |
| `db/dump/*-full*.sql` | — | ⚠️ 可选 | 含测试账号密码哈希，只在需要恢复数据时带 |

**推荐做法**：拷整个项目目录，但排除上表标 ❌ 的项。或者在项目里执行一次：

```powershell
# 只导出需要的部分到 U 盘（把 E:\ 换成你的盘符）
robocopy . E:\personal-ledger /E /XD node_modules target dist .idea .git .skills /XF *.log
```

## 二、新电脑上的三种情况

### 情况 A：能联网（最常见）

在项目根目录执行一键初始化：

```powershell
.\setup.ps1
```

它会依次：

1. 检查 `java` / `mvn` / `mysql` 是否在 PATH（`node` 可选）
2. 检查 Java 版本 ≥ 17
3. 用给定凭据连接 MySQL
4. **创建数据库（若不存在）** —— 只创建空库，**不会删除或覆盖任何已有数据**
5. 检查 Maven 本地仓库
6. `mvn clean package` 构建 jar
7. 打印启动方式

如果 MySQL 密码不是默认的 `123456`：

```powershell
.\setup.ps1 -DbPassword "你的密码"
```

### 情况 B：不能联网，但你能提前准备

在**有网的机器上**先把依赖预热进项目目录：

```powershell
cd backend
mvn -B -Dmaven.repo.local="..\.m2-portable" dependency:go-offline
mvn -B -Dmaven.repo.local="..\.m2-portable" clean package -DskipTests
```

这会生成项目根目录下的 **`.m2-portable\`**（约 200–400 MB）。

`pom.xml` 里有一个 profile 会**自动检测这个目录**并把它当作本地仓库：

```xml
<profile>
  <id>portable-offline-repo</id>
  <activation>
    <file><exists>${maven.multiModuleProjectDirectory}/.m2-portable</exists></file>
  </activation>
  <properties>
    <maven.repo.local>${maven.multiModuleProjectDirectory}/.m2-portable</maven.repo.local>
  </properties>
</profile>
```

路径用 `${maven.multiModuleProjectDirectory}`（Maven 自动注入的项目根目录）拼出来，
所以**拷到哪个盘符都能用**，这一点和之前写死 `D:\m2repo` 的做法完全不同。

代价：U 盘要多拷 200–400 MB。若目标机器能联网就没必要。

### 情况 C：只想运行，不想构建

`backend/target/*.jar` 是**自包含**的（Spring Boot fat jar，含全部依赖与前端产物）。
直接把它拷过去就能跑，不需要 Maven，甚至不需要源码：

```powershell
java -jar personal-ledger-1.0.0-SNAPSHOT.jar
```

前提是目标机器**有 JDK 17+ 和 MySQL**。

## 三、数据库凭据怎么改

`application.yml` 里全部支持环境变量覆盖，**不需要改代码或改配置文件**：

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DB_HOST` | `127.0.0.1` | MySQL 地址 |
| `DB_PORT` | `3306` | 端口 |
| `DB_NAME` | `personal_ledger` | 库名 |
| `DB_USERNAME` | `root` | 用户名 |
| `DB_PASSWORD` | `123456` | 密码 |
| `APP_JWT_SECRET` | 开发用默认值 | **生产必须改**，至少 32 字节 |

PowerShell 里这样设置（只在当前窗口有效）：

```powershell
$env:DB_USERNAME = 'root'
$env:DB_PASSWORD = 'your-password'
$env:APP_JWT_SECRET = 'a-random-string-at-least-32-bytes-long'
```

在 IDEA 里则配在 **Run → Edit Configurations → Environment variables**，
比改配置文件更安全（不会误提交）。

> **为什么不在 `application.yml` 里留真实的密码和密钥？**
> 那份文件是提交进版本库的。默认值只是本地开发的便利值，
> 真实凭据必须走环境变量。

## 四、在 IDEA 里打开

1. **打开 `backend` 目录**（不是项目根目录）。
   IDEA 会识别 `pom.xml` 并导入为 Maven 项目。
   > 建议从根目录打开时只把 `backend/pom.xml` 作为 Maven 项目导入 ——
   > 根目录下没有 pom，直接打开根目录会被当成普通 Java 模块。

2. 如果依赖下载慢，启用阿里云镜像（可选）：
   `Settings` → `Build, Execution, Deployment` → `Build Tools` → `Maven`
   → **User settings file** 指向 `<项目>\backend\settings.xml.optional`（勾选 Override）

   > 这个文件**默认不生效**，必须手动指定才加载。它只配置镜像，
   > 不再写死本地仓库路径 —— 之前那个写死 `D:\m2repo` 的 `settings.xml`
   > 已经删除，它是项目可移植性最大的障碍。

3. 在 Maven 面板执行一次 `Lifecycle` → **`package`**
   （`spring-boot:run` 和直接运行 main 类都依赖 `target/classes` 里已有编译好的类与资源）

4. 运行 `com.example.ledger.LedgerApplication`

5. 打开 **http://127.0.0.1:8080** —— 前后端同源，不需要另起前端服务

## 五、要改前端时才需要 Node

运行项目**不需要 Node** —— 编译好的前端已经提交在
`backend/src/main/resources/static/`，并被打进 jar。

只有修改前端源码时才需要：

```powershell
cd frontend
npm install          # 首次，需要联网
npm run dev          # 开发服务器 http://127.0.0.1:5173（/api 代理到 8080）
npm run build        # 产物直接输出到 backend/src/main/resources/static/
```

改完前端后要重新 `mvn package` 才能让 jar 带上新产物。

> ⚠️ `npm run dev` 用完请用 **Ctrl+C 正常退出**。直接关窗口会让 Vite 的 node
> 子进程变成孤儿进程残留（本项目遇到过，会占内存并干扰后续排查）。

## 六、被移除的可移植性障碍

改造前后对比，便于理解为什么这么设计：

| 项 | 改造前 | 改造后 |
| --- | --- | --- |
| Maven 本地仓库 | `settings.xml` 写死 `D:\m2repo` | 默认用 `~/.m2/repository`；需要离线时用项目内 `.m2-portable`（相对路径，自动检测） |
| 阿里云镜像 | 在自动加载的 `settings.xml` 里 | 移到 `settings.xml.optional`，**必须手动启用** |
| Maven 参数 | `.mvn/maven.config` 自动附加 `-s settings.xml` | 已删除；命令行与 IDEA 行为一致 |
| 数据库凭据 | 硬编码在 `application.yml` | 环境变量覆盖，默认值仅本地便利 |
| 前端产物 | 需要在新机器上 `npm install && npm run build` | **已提交**，jar 里就有 |
| 初始化步骤 | 手工建库、手工跑 SQL、手工打 jar | `.\setup.ps1` 一条命令 |

**唯一还需要手工判断的**是目标机器的 MySQL 凭据 —— 这是设计使然，
数据库口令不该由项目携带。

## 七、常见问题

**Q: `setup.ps1` 报 "not found on PATH"**
装对应工具并**重开终端**（PATH 变更需要新会话）。版本要求见本文档第一节。

**Q: MySQL 连不上，但密码是对的**
检查服务是否启动：`Get-Service MySQL80`。若服务名不同（如 `MySQL84`），用
`Get-Service *mysql*` 查。

**Q: 打开页面空白**
先确认直接访问 `http://127.0.0.1:8080/assets/` 下的 js 能取到。
若返回 401，说明 `SecurityConfig` 里的静态资源白名单没跟上前端构建产物的路径 ——
这是改前端目录结构时容易踩的坑（本项目把 `/vendor/**` 改成 `/assets/**` 就是因为这个）。

**Q: Flyway 报 "Found non-empty schema but no schema history table"**
说明库里有表但不是 Flyway 建的。配置里已开启 `baseline-on-migrate`，
正常情况下会自动建基线。若仍报错，检查 `application.yml` 的 `spring.flyway` 段是否被改动。

**Q: 在别的机器上 Flyway 报 checksum 不匹配**
说明有人改了已执行过的迁移脚本（`V1__baseline.sql` / `V2__add_user_deleted_at.sql` / `V3__drop_ledger_uk_reversal_once.sql`）。
**已执行过的迁移脚本永远不要改**，要改结构就新增 `V3__*.sql`。

**Q: 能不能不用 MySQL，做成一个文件？**
那是换 SQLite 的方案，属于架构级改动（要改依赖、Flyway 方言，
以及 `LEAST`、`CONCAT`、`information_schema` 等 MySQL 专有 SQL）。
详见 [数据库备份说明](数据库备份说明.md) 第五节。
