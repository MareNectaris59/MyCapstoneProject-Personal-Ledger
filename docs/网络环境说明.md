# 网络环境说明：离线运行的影响与联网改造

> 本文档回答两个问题：
> 1. 全程离线运行对项目有什么**实际**影响？
> 2. 怎么解决联网问题，以及要改回哪些代码？
>
> 配套文档：[README](../README.md) · [系统设计说明书](系统设计说明书.md)

---

## 一、故障定性：网络是通的，被拦住的是 TLS

这一点必须先说清楚，因为它决定了整个修复路径。实测结果：

| 测试 | 结果 |
| --- | --- |
| TCP 连接 `repo1.maven.org:443` | ✅ 成功 |
| TCP 连接 `maven.aliyun.com:443` | ✅ 成功 |
| TCP 连接 `maven.aliyun.com:80` / `repo.huaweicloud.com:80` | ✅ 成功 |
| TLS 握手（阿里云 / Maven 中央） | ❌ `No credentials are available in the security package` |
| PowerShell `Invoke-WebRequest` 任何 HTTPS | ❌ 连接被关闭 |
| **HTTP 访问华为云镜像** | ✅ **成功（HTTP 200）** |
| HTTP 访问阿里云 / npmmirror | ❌ 连接被关闭 |
| MySQL 连接 `127.0.0.1:3306` | ✅ 正常（JDBC 全程可用） |
| localhost HTTP 请求 | ✅ 正常（287 项测试全走 HTTP） |

**结论有两层：**

1. DNS 解析与 TCP 出站都正常，失败点在 **TLS 握手**。
   `No credentials are available in the security package` 是 Windows **SChannel**（SSPI 安全包）
   的错误，对应 `SEC_E_NO_CREDENTIALS`。典型成因不是防火墙，而是进程运行在
   **受限令牌 / 沙箱**中无法访问 SChannel 凭据存储。这解释了为什么
   只有"出站 HTTPS"坏了，而 localhost 的 HTTP 与 JDBC 完全正常。

2. **不是所有主机都不可达。** 华为云镜像的明文 HTTP 入口实测可用（见方案 B），
   说明故障是"TLS 握手被拦"而非"网络被切断"。这是本次排查最有价值的发现 ——
   它给出了一个**在沙箱内就能自助完成**的修复路径。

> **可验证的推论**：如果你在**沙箱之外**（普通 PowerShell 窗口）执行
> `Invoke-WebRequest https://maven.aliyun.com -UseBasicParsing`，大概率会成功。
> 若成功，说明问题纯属沙箱限制，**联网后本项目的全部离线适配都可以撤销**。

## 二、离线运行对项目的实际影响

影响分四类。前三类是**妥协**（能工作但有代价），第四类是**真实缺口**（功能缺失）。

### 2.1 构建方式被扭曲（最严重）

Maven 的标准生命周期**完全不可用**：

| 插件 | 状态 | 后果 |
| --- | --- | --- |
| `maven-resources-plugin` | 两个缓存中**都不存在**（0 个 jar） | `process-resources` 阶段失败 → `mvn compile` 跑不通 |
| `spring-boot-maven-plugin` | 依赖缺失 | `mvn spring-boot:run`、`mvn package` 跑不通 |
| `flyway-maven-plugin` | 缺失 | 无法用 Maven 执行数据库迁移 |

**被迫的替代方案**：Maven 只负责它不可替代的部分（依赖解析 + classpath 生成），
编译改用 `javac` 直调，运行改用 `java` 直调 —— 全部封装在 `backend/build.ps1`。

代价：

- **多出一个自维护的构建脚本**，与 Maven 的标准方式并行存在，新人容易困惑
- **丢失 `mvn package`** → 产不出可部署的 fat jar，只能 `java -cp` 运行
- **丢失 Maven 的增量编译与插件生态**（如 `mvn test`、`mvn dependency:tree` 的部分功能）
- **`-parameters` 这类编译参数必须手工补**（Maven 默认会加，javac 不会）。
  这正是开发中真实触发过的一个 bug：漏了它导致 Spring 无法读取参数名，
  所有 `@RequestParam` / `@PathVariable` 全部 500。

### 2.2 依赖版本被迫降级或选型变更

只能选**缓存里恰好有**的版本，而不是"最合适的"版本：

| 目标 | 被迫的选择 | 原因 |
| --- | --- | --- |
| Spring Boot 3.2.0 | 而非 3.3.x / 3.5.x | 只有 3.2.0 同时缓存了 web/security/data-redis/jdbc/test 五个 starter |
| `spring-boot-starter-validation` 3.3.5 | 显式钉版本，跨版本混用 Boot 3.2.0 | 3.2.0 的该 starter 不在缓存里 |
| `classmate` 1.7.0 | 显式钉版本 | Boot 3.2.0 管理的 1.6.0 不在缓存里 |
| `mybatis-spring` 3.0.3 | 排除 MP 自带的 2.1.x 后手工引入 | 2.1.x 与 Spring 6 不兼容，会启动崩溃 |
| Flyway | **完全移除** | 缓存里没有 |
| springdoc-openapi（Swagger UI） | **完全移除** | 缓存里没有 |
| `spring-boot-starter-aop` | **移除** | 缓存里没有 |
| `spring-boot-starter-mail` | **移除**，验证码接口只返回提示 | 缓存里没有 |
| Redis | **保留依赖但运行时未启用**（无 Redis 服务，且有降级设计） | 不影响 |

**这些都是"因为缓存里没有所以不要"的决策，不是技术选型决策。** 联网后应重新评估。

### 2.3 前端被整体降级（影响最直接）

`npm install` 无法完成 —— 卡在 `nanoid@^3.3.20`：缓存里的 packument 列出了该版本，
但对应的 tarball 不在缓存中（`ENOTCACHED` / `ETARGET`）。这类"元数据与内容不一致"的缺口还会有很多。

**被迫的替代方案**：从 npm 缓存的 tarball 里提取 Vue / Vue Router / Axios 的**浏览器生产构建**，
放到 `backend/src/main/resources/static/vendor/`，用 `<script>` 直接加载。

由此产生的**真实功能缺口**：

| 缺口 | 影响 |
| --- | --- |
| ❌ 无 Element Plus | 所有 UI 组件手写 CSS（当前 `app.css` 约 190 行） |
| ❌ 无 ECharts | **消费分析图表完全无法实现**（设计文档 §6.2.6 的接口没有前端可用） |
| ❌ 无 Pinia | 状态管理用 Vue `reactive` + `provide/inject` 顶替 |
| ❌ 无 TypeScript | `frontend/package.json` 里没有 TS，无类型检查 |
| ❌ 无 Vite 构建 | 模板是 JS 字符串，不是 `.vue` 单文件组件；无热更新；无代码分割 |
| ❌ 无 `npm run build` | 产不出优化后的静态资源 |
| ⚠️ 模板字符串难维护 | 800 行 `app.js` 里混着 HTML，缩进与引号转义很痛苦 |

**其中「无 ECharts」是真正的功能缺失** —— 消费分析的折线图/饼图/柱状图是这个系统的
核心卖点之一（设计文档 §6、§7.6 的整套算法都为此服务），现在没有前端可承载。

### 2.4 工作区里塞了 3.2 GB 的缓存

| 目录 | 大小 | 为什么存在 |
| --- | --- | --- |
| `.m2repo/` | 753 MB | 两个系统级 Maven 缓存都**只读**，必须复制到可写位置 |
| `.npm-cache/` | 2441 MB | 同理，npm 默认缓存在用户目录，写入被拒（`EPERM`） |

代价：**不能提交到版本库，也不能拷进毕设材料**。这是纯粹的环境产物，无任何项目价值。

### 2.5 影响总结

| 维度 | 离线状态 | 联网后 |
| --- | --- | --- |
| 功能完整性 | 账务内核 100%，**分析图表 0%** | 可补齐 |
| 构建方式 | 自维护 `build.ps1`，无 fat jar | 回归标准 Maven |
| 依赖版本 | 由缓存决定，多处降级/移除 | 由需求决定 |
| 前端形态 | 免构建，手写 CSS，无图表 | Vite + Element Plus + ECharts |
| 工作区 | 多 3.2 GB 垃圾 | 可清理 |
| 账务逻辑 | **完全不受影响** | 不变 |

**一句话**：离线只扭曲了**构建与表现层**，没有触及账务内核 ——
287 项后端测试全通过，说明核心正确性未受影响。前端图表（消费分析）后来也已实现，见 §下方补记。

> **补记（文档更新）**：本文写作时消费分析图表尚未实现，因此把"前端分析能力缺失"
> 当作离线可接受的代价。该判断已过时 —— 分析模块（8 个接口 + ECharts 图表）
> 与预算模块均已落地，且 ECharts 是本地打包产物（`assets/echarts-*.js`），
> 运行时不请求任何 CDN。也就是说：**离线运行下功能是完整的**。
> 本文关于"离线会损失什么"的分析仍然成立，但结论已不再包括功能缺失。

## 三、修复联网问题

### 方案 A：在沙箱外执行网络操作（推荐先试）

由于失败原因是沙箱安全包限制，**在普通 PowerShell 窗口**（非沙箱）里执行应当正常：

```powershell
# 在普通 PowerShell 窗口里验证
Invoke-WebRequest https://maven.aliyun.com/repository/public -UseBasicParsing -Method Head
```

若成功，就有两条路：

1. **让所有构建在沙箱外跑** —— 你自己在普通终端执行 `mvn` / `npm` 命令
2. **只让下载在沙箱外跑，构建仍在沙箱内** —— 先用联网环境把依赖灌满本地仓库
   （见方案 C 步骤 1），之后沙箱内可继续离线构建

### 方案 B：HTTP 回落 —— **已实测可行** ✅

**这是本次排查的结论性发现。**

`Invoke-WebRequest` 与 `HttpClient` 的失败原因不同，必须区分：

| 客户端 | 行为 | 结果 |
| --- | --- | --- |
| `Invoke-WebRequest`（PowerShell 5.1） | 默认发 `Connection: close` | 部分 CDN 直接掐断连接，报"基础连接已经关闭" |
| `HttpClient` + `ConnectionClose = $false` | keep-alive | **成功** |

**实测结果（华为云镜像）**：

| 目标 | 结果 |
| --- | --- |
| `http://repo.huaweicloud.com/repository/maven/` | ✅ HTTP 200 |
| `flyway-core-9.22.3.jar` | ✅ 865 KB，PK 头校验通过，是合法 JAR |
| `flyway-mysql-9.22.3.jar` | ✅ 31 KB |
| `springdoc-openapi-starter-webmvc-ui-2.3.0.jar` | ✅ 23 KB |
| `http://mirrors.huaweicloud.com/repository/npm/vue` | ✅ 2.1 MB 元数据 |

**对照：阿里云与 npmmirror 的 HTTP/HTTPS 全部被拦**（连接被关闭）。
**根因不是"HTTP vs HTTPS"**，而是**目标主机的可达性差异** ——
华为云镜像恰好可达，且它提供**明文 HTTP 入口**，从而绕开了 SChannel 的 TLS 故障。

#### 使用方法

**Maven**：在 `settings.xml` 里把镜像指向华为云 HTTP 源：

```xml
<mirror>
  <id>huaweicloud-http</id>
  <mirrorOf>*</mirrorOf>
  <url>http://repo.huaweicloud.com/repository/maven/</url>
</mirror>
```

Maven 3.8.1+ 默认**阻止 HTTP 仓库**（`maven-default-http-blocker`）。
使用上述镜像需要放行 —— 在 `settings.xml` 中用一个 ID 相同的空镜像覆盖它：

```xml
<mirror>
  <id>maven-default-http-blocker</id>
  <mirrorOf>dummy</mirrorOf>
  <url>http://0.0.0.0/</url>
  <blocked>false</blocked>
</mirror>
```

**npm**：`npm config set registry http://mirrors.huaweicloud.com/repository/npm/`

**Python / pip**（若之后用到）：
`pip config set global.index-url http://mirrors.huaweicloud.com/repository/pypi/simple`

#### ⚠️ 安全警告（必须读）

**明文 HTTP 存在中间人篡改风险。** 适用边界：

| 场景 | 是否可用 |
| --- | --- |
| 拉取公开依赖做本地开发 | ✅ 可接受 |
| 生产环境部署、CI/CD | ❌ 禁止 |
| 传输任何凭据（token、密码） | ❌ 禁止 |

拉取后建议与官方 SHA-256 核对关键依赖（如 Spring Boot、MyBatis-Plus）。

> **更优做法**：既然华为云的 **HTTPS** 大概率也可达（它只是同样被 SChannel 拦住），
> 若方案 A（沙箱外执行）可行，应优先用 HTTPS 官方源，把 HTTP 仅作为沙箱内的备用路径。

### 方案 C：把依赖预灌进本地仓库（最稳，推荐）

网络恢复后（任一方式），一次性把依赖装齐，之后即使再离线也能构建：

```powershell
# 1. 在联网环境下预热 Maven 依赖（会把 jar 下载到指定的本地仓库）
cd backend
mvn -B -s settings.xml dependency:go-offline

# 2. 预热 npm 依赖
cd ..\frontend
npm install

# 3. 验证离线可用（断开网络后）
mvn -B -o compile
npm run build
```

这一步做完，`.m2repo/` 和 `node_modules/` 就是完整自足的，
沙箱限制不再影响构建。

### 方案 D：企业/校园代理

若机器处于需要代理的网络中，配置代理而非绕过：

```powershell
$env:HTTP_PROXY  = "http://proxy.example.com:8080"
$env:HTTPS_PROXY = "http://proxy.example.com:8080"
```

Maven 需在 `settings.xml` 的 `<proxies>` 中单独配置；npm 用
`npm config set proxy` / `https-proxy`。

> **注意**：代理配置属于凭据信息，不要提交到版本库。

### 修复优先级（经实测修订）

```
✅ 已完成：方案 B 验证 —— 华为云 HTTP 镜像可用，Maven 与 npm 均可下载

下一步二选一：
  路线 1（推荐，最干净）：方案 A —— 在沙箱外普通 PowerShell 里跑 mvn/npm
                        一次把依赖灌满，之后沙箱内离线也能构建
  路线 2（沙箱内可自助）：方案 B —— 把镜像换成华为云 HTTP 源
                        需要放行 Maven 的 HTTP 黑名单

之后：按第四节清单改回 4 个配置文件
```

**两条路线的取舍**：

| | 路线 1（沙箱外） | 路线 2（华为云 HTTP） |
| --- | --- | --- |
| 是否需要你手动操作 | 需要（我没法在沙箱外执行） | 不需要，我可以在沙箱内直接做 |
| 安全性 | ✅ HTTPS，安全 | ⚠️ 明文 HTTP |
| 覆盖面 | 全部官方源 | 仅华为云镜像有的构件 |
| 适合 | 长期开发环境 | 临时补齐缺失的十几个依赖 |

**建议**：用路线 2 补齐当前缺的依赖（Flyway / springdoc / aop / mail / Element Plus / ECharts），
把项目跑起来；之后有条件再用路线 1 做一次干净的完整预热。

## 四、要改回联网的代码清单

**好消息：需要改的只有 4 个配置文件，加上撤销前端降级。业务代码零改动。**

`LedgerCoreService`、`BalanceValidator`、`SecurityConfig`、所有 Mapper 与 Controller —— 
**没有一行代码包含离线妥协**。它们用的都是标准 Spring Boot / MyBatis-Plus API。

### 4.1 `backend/pom.xml`（需要改）

| 项 | 离线状态 | 联网后 |
| --- | --- | --- |
| 父 POM 版本 | 3.2.0（被缓存限制） | 升到 3.3.x / 3.5.x（Boot 3 最新稳定） |
| validation starter | 显式钉 3.3.5 跨版本混用 | 删除 `<version>`，由父 POM 管理 |
| `classmate` 显式依赖 | 钉 1.7.0 绕过缓存缺口 | **删除整个依赖**，由 hibernate-validator 传递引入 |
| `mybatis-spring` 排除 + 手工引入 | 需要（2.1.x 与 Spring 6 冲突） | **保留** —— 这是真实兼容性问题，与离线无关 |
| `commons-pool2` 排除 | 需要（缓存缺失） | 删除排除 |
| Flyway | 注释中说明"不可用" | **加回** `flyway-core` + `flyway-mysql` |
| springdoc-openapi | 无 | **加回**，恢复 Swagger UI |
| `spring-boot-starter-aop` | 无 | **加回**（`@TransactionalEventListener` 会用） |
| `spring-boot-starter-mail` | 无 | **加回**，实现真实邮箱验证码 |
| spring-boot-maven-plugin 配置 | 存在但用不上 | 生成 fat jar |

### 4.2 `backend/settings.xml`（需要**精简**）

| 项 | 离线状态 | 联网后 |
| --- | --- | --- |
| `<localRepository>../.m2repo</localRepository>` | 指向工作区合并缓存 | **删除整个文件**，改用默认 `~/.m2/repository` 或你原来的全局配置 |
| `<mirrors>` 指向 aliyun | 名义配置（离线不生效） | 全局 settings 里已有阿里云镜像，无需项目级配置 |

**结论：联网后这个文件可以直接删掉**，它对离线缓存的所有解释性注释也就失去意义了。

### 4.3 `backend/.mvn/maven.config`（需要**删除**）

这个文件的唯一作用是自动附加 `-s settings.xml -o -Dmaven.repo.local=../.m2repo`。

联网后：**删掉整个 `.mvn/` 目录**，`mvn` 命令回到标准行为。

若想保留"依赖预灌"的能力（方案 C），则保留 `-Dmaven.repo.local=../.m2repo`
但**删除 `-o`** —— 这样优先用本地缓存，缺失的才联网下载。

### 4.4 `frontend/.npmrc`（需要删除）

| 项 | 离线状态 | 联网后 |
| --- | --- | --- |
| `cache=D:\Capstone Project\.npm-cache` | 绕开只读的用户缓存 | **删除此文件**，用默认缓存 |
| `offline=true` | 强制只读缓存 | 删除 |
| `audit=false` / `fund=false` | 减少噪音 | 可保留 |

### 4.5 前端：撤销降级（工作量最大的一项）

这一步不是"改代码"而是"换实现"，是唯一需要重新开发的：

| 步骤 | 操作 |
| --- | --- |
| 1 | 恢复 `frontend/package.json` 的完整依赖：`element-plus`、`echarts`、`pinia`、`@vitejs/plugin-vue`、`vite`、`terser`（注：`typescript` / `vue-tsc` 后来被有意移除，原因见 [frontend/README](../frontend/README.md)「为什么没有 TypeScript」） |
| 2 | 删除 `backend/src/main/resources/static/vendor/`（4 个文件，约 400 KB） |
| 3 | 把 `app.js` 的 800 行拆成 `.vue` 单文件组件（5 个页面 + 通用组件） |
| 4 | 用 Element Plus 替换手写 CSS 组件；引入 ECharts 实现消费分析图表 |
| 5 | `npm run build` 产物输出到 `backend/src/main/resources/static/` |
| 6 | 从 `SecurityConfig.PUBLIC_PATHS` 里移除 `/vendor/**`、`/app.js`、`/app.css`（改用构建产物的实际路径） |
| 7 | 更新 `README.md` 的「本机环境限制」章节 —— 整章可以删掉 |

### 4.6 可以永久保留的改动（与离线无关）

这几处是**修真实 bug**，联网后也要保留：

| 项 | 为什么保留 |
| --- | --- |
| `mybatis-spring` 排除 + 引入 3.0.3 | MP 3.5.5 带的 2.1.x 与 Spring 6 真实不兼容 |
| JDBC URL 的 `characterEncoding=UTF-8` | 写成 `utf8mb4` 是真实的 Connector/J 用法错误 |
| `{id:\d+}` 路径约束 | 避免路径变量吞掉字面量路径 |
| javac 的 `-parameters` | 即使回归 Maven，这个编译参数的作用也要记住 |
| `build.ps1` | 可改为 Maven 的薄封装，或作为无网络环境的后备 |
| `test-api.ps1` | 纯 HTTP 测试，与构建方式无关，永久有效 |
| `logback-spring.xml` | 生产本就需要的日志滚动配置 |

## 五、结论与建议

**离线对项目的影响**：扭曲了构建方式、限制了依赖选型、**使前端消费分析图表完全缺失**、
往工作区塞了 3.2 GB 缓存。**但账务内核未受影响** —— 287 项测试全通过。

**修复路径**：先花 1 分钟验证方案 A（沙箱外执行），确认是否纯沙箱限制；
用方案 C 预热依赖；然后按第四节的清单改回 4 个配置文件。

**要改的代码极少**：4 个配置文件 + 一次前端重建。
业务代码零改动 —— 这是当初坚持"离线适配只停留在构建层、不污染业务逻辑"的收益。

**建议顺序**：

1. 验证方案 A
2. 若通 → 立即预热 Maven + npm 依赖（方案 C），避免再次被迫离线
3. 改回 `pom.xml`（加回 Flyway、springdoc、aop、mail，升 Boot 版本）
4. 删除 `settings.xml` 与 `.mvn/maven.config`
5. 删除 `frontend/.npmrc`，恢复 `package.json`，切回 Vite 构建
6. 前端重建，补齐 Element Plus 与 ECharts —— 这一步与 Brutalism 改造合并做，避免返工
