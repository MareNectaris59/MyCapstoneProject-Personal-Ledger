# 数据库备份说明

本文档说明如何把数据库导出到项目目录，供备份、迁移与提交材料使用。

> **结论先说**：数据库本身**没有**搬进项目目录 —— 那需要改 MySQL 的 `datadir`，
> 会影响实例上另外 19 个库。本项目改用「导出 `.sql` 到项目内」的方式，
> 达到同样的目的（数据跟着项目走、可单独备份、可提交），风险为零。

---

## 一、为什么不直接搬 MySQL 的数据库文件

MySQL 的数据目录是**整个服务实例共用**的，不是本项目独占：

```
C:\ProgramData\MySQL\MySQL Server 8.0\Data\      ← datadir
    ├── personal_ledger\    本项目（1.03 MB）
    ├── sakila\             6.45 MB
    ├── world\              0.77 MB
    ├── leadnews_article\   leadnews_user\   leadnews_wemedia\
    ├── dorm_db\  shop\  sport\  sport_db\  account_book\
    ├── product_manage\  passenger_refund_db\  springwebdata\
    ├── student_db\  dwj_db\  demo\  sys\  mysql\ ...
```

要把 `datadir` 移到 `D:\Capstone Project`，意味着：

| 步骤 | 风险 |
| --- | --- |
| 停止 MySQL80 服务 | 所有项目的数据服务中断 |
| 复制整个 Data 目录（约 12 MB） | 复制不完整会损坏 InnoDB |
| 改 `C:\ProgramData\MySQL\MySQL Server 8.0\my.ini` 的 `datadir` | 写错服务起不来 |
| 处理目录权限 | MySQL 服务账户需对新路径有完全控制权，否则报 `Can't create/write to file` |
| 重启并验证 20 个库 | 任一步出错，**全部库一起打不开** |

还有两个说不通的地方：

1. **项目会进 Git** —— 数据库文件放进去就会被提交，而 `.ibd` 二进制文件既不可读也不可 diff
2. **`.ibd` 不能单独取用** —— 它必须和 `ibdata1`、`undo`、`redo` 日志一起才构成可用的 datadir。
   也就是说"把 personal_ledger 的 db 文件拿出来"这件事**本身就不成立**，只能整目录搬

而 `.sql` 导出正好相反：单文件、纯文本、可读、可 diff、可在任何机器还原。

## 二、怎么用

### 导出

在项目根目录执行：

```powershell
# 完整导出（结构 + 数据），文件名自动带时间戳
.\backup-db.ps1

# 只导出结构，不含任何测试数据 —— 交材料/公开仓库用这个
.\backup-db.ps1 -SchemaOnly

# 自定义文件名
.\backup-db.ps1 -Name before-refactor

# 导出实例上全部数据库（慎用，会含其他项目的数据）
.\backup-db.ps1 -AllDatabases
```

产物落在 **`db\dump\`**：

```
db/dump/
├── personal_ledger-schema-20261014-164000.sql    ← 结构，可提交
├── personal_ledger-full-20261014-164000.sql      ← 含数据，已 gitignore
└── before-refactor.sql
```

### 还原

```powershell
mysql -u root -p < "db\dump\personal_ledger-schema-20261014-164000.sql"
```

脚本用的是 `--databases` 参数，导出文件里含 `CREATE DATABASE` 与 `USE`，
所以**不需要先建库**，直接执行即可。

### 脚本做了什么

| 参数 | 作用 |
| --- | --- |
| `--single-transaction` | 一致性快照，导出期间不锁表 |
| `--routines --triggers --events` | 存储过程、触发器、事件一并导出 |
| `--set-gtid-purged=OFF` | 去掉 GTID 语句，否则还原到别的实例会报错 |
| `--default-character-set=utf8mb4` | 保证中文与 emoji 不损坏 |
| 通过 `cmd.exe` 重定向 | **关键**：PowerShell 5.1 的 `>` 会以 UTF-16 加 BOM 写入，破坏 mysqldump 的 UTF-8 输出 |

脚本末尾会自检导出文件是否含 `CREATE TABLE`，为空或截断会返回非零退出码 —— 因为
"导出了一个空文件"是这类脚本最常见的静默失败。

## 三、什么该提交、什么不该

`.gitignore` 的规则是：**只提交结构导出**。

```gitignore
db/dump/*.sql
!db/dump/*-schema.sql
```

原因：完整导出里含**测试账号邮箱与 BCrypt 密码哈希**。虽然是测试数据，
但把凭据类内容提交进仓库不是好习惯。交材料前建议再确认一次：

```powershell
.\backup-db.ps1 -SchemaOnly          # 用这个交材料
Select-String -Path db\dump\*.sql -Pattern '@example.com'   # 应无输出
```

## 四、与 Flyway 的关系

项目同时有两条结构管理路径，职责不同，**不要混淆**：

| 路径 | 文件 | 用途 |
| --- | --- | --- |
| **Flyway 迁移** | `backend/src/main/resources/db/migration/V*.sql` | 应用启动时**自动执行**，保证任何环境的表结构一致。这是权威来源 |
| **dump 导出** | `db/dump/*.sql` | 人工备份、迁移到另一台机器、交材料。**不要用它替代迁移** |

改表结构时的正确顺序：

1. 改 `docs/数据库设计.md`
2. 新增 `V3__xxx.sql`（**不要改已执行过的 V1/V2**，Flyway 会校验 checksum 并拒绝启动）
3. 重启应用，Flyway 自动应用
4. 如需备份，再跑 `.\backup-db.ps1`

## 五、如果确实需要"一个文件就能跑"的数据库

那是另一个方案：改用 **SQLite** —— 数据库就是项目里一个 `.db` 文件，
拷走即可运行，不依赖任何服务。代价是要改：

- `pom.xml` 依赖（`mysql-connector-j` → `sqlite-jdbc`）
- Flyway 方言与迁移脚本（SQLite 的 `ALTER TABLE` 能力有限，本项目的
  `V2` 那种加列写法需要调整）
- 部分 SQL：现在用到了 MySQL 的 `LEAST`、`CONCAT`、`information_schema` 查询，
  以及 `utf8mb4_0900_ai_ci` 排序规则，这些在 SQLite 上都要重写

这属于架构级改动，与"备份"是两件事。若要做，应当作为独立任务计划。
