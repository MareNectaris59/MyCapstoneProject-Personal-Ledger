## 二、功能清单

### 2.1 账号与登录（9 个接口）

| 功能 | 说明 |
| --- | --- |
| 注册 | 邮箱 + 密码，创建用户时自动生成完整科目树 |
| 登录 | 返回 access token（短效）+ refresh token（长效） |
| 令牌刷新 | 用 refresh token 换新的 access token |
| 登出 | 清除本地凭证 |
| 查看资料 | 昵称、邮箱 |
| 修改昵称 | |
| 修改密码 | **改密即踢下线**：`token_version` 自增，此前签发的令牌立即失效 |
| 注销账户 | 软注销：账号失效、个人信息清除，**账务流水保留**（物理删除会破坏 append-only） |
| 登录失败限流 | 同一「邮箱 + 客户端 IP」10 分钟内失败 5 次即拒绝，返回 1204 |

### 2.3 记账（9 个接口）

| 功能 | 说明 |
| --- | --- |
| 记支出 | 借费用科目 / 贷资产账户 |
| 记收入 | 借资产账户 / 贷收入科目 |
| 记转账 | 借转入账户 / 贷转出账户 |

| 修改 / 删除 | |
| 执行情况 | 已用额、执行率、剩余额、当前周期窗口 |
| 周期列表 | 每个历史周期的额度与执行记录 |
| 预警列表 | 未读预警 |
| 标记已读 | |

### 2.5 消费分析（8 个接口）

| 功能 | 说明 |
| --- | --- |
| 总览 | 收入、支出、结余、笔数 |
| 分类占比 | 支持多层级下钻 |
| 趋势 | DAY / WEEK / MONTH / YEAR 四种粒度，非法粒度显式返回 1101 |
| 同比 / 环比 | 含**基期对齐**：当前周期未结束时自动裁剪基期至等长 |
| 增减贡献 | 哪些分类导致了支出变化 |
| 预算执行分析 | 各预算的执行率汇总 |
| 周期报表 | 单个周期的完整报表 |
| CSV 导出 | 带 UTF-8 BOM，Excel 直接可读 |

### 2.6 定期记账（5 个接口）

| 功能 | 说明 |
| --- | --- |
| 新建规则 | 名称、类型、金额、科目、对方账户、频率（每周 / 每月）、起始日、结束日 |
| 规则列表 | 含名称解析、下次记账日、启用状态 |
| 修改规则 | 只开放金额、备注、启用、结束日（改类型/科目/频率会影响已生成账目） |
| 删除规则 | 逻辑删除，已生成的账目不受影响 |
| 立即执行 | 手动触发到期规则，不必等到凌晨 |

关键行为：

- **定时执行**：每日 00:10 由 `@Scheduled` 触发
- **补跑**：应用停机多日后重启，错过的每一期都会补上，单次上限 366 期
- **幂等**：幂等键 `rec-<规则ID>-<执行日>`，无论定时任务、手动触发还是失败重试，同一期只记一笔
- **月末锚定**：锚定 31 号的规则在跨过短月后退让，之后回到 31 号（`1/31 → 2/28 → 3/31`），不随时间漂移
- **失败隔离**：单条规则校验失败只记日志并保留待下次重试，不影响其他用户

## 三、账务内核的硬保证

这些能力在界面上看不出来，但决定了系统是否"真的是一套复式记账"。

| 保证 | 实现方式 |
| --- | --- |
| 借贷必须平衡 | 每张凭证写入前校验「借方合计 = 贷方合计」 |
| 只能记末级科目 | `is_leaf = 1` 才可记账（BR-10） |
| 账目不可修改、不可删除 | append-only；纠正只能通过反向分录 |
| 冲正支持部分金额 | 按原分录金额比例拆分，舍入差额由最后一条吸收，冲正本身也可再被冲 |
| 重复提交不重复记账 | 幂等键：接口由客户端传入，导入按「文件哈希 + 行号」，定期按「规则 ID + 执行日」 |
| 并发安全 | 原子日序号 + 数据库 `SELECT MAX(ledger_no)` 兜底，100 线程并发记账验证通过 |
| 余额可验证 | 缓存余额与「由分录重算的真值」双轨比对，提供对账接口 |

## 四、安全

| 项 | 实现 |
| --- | --- |
| 密码存储 | BCrypt |
| 登录限流 | 「邮箱 + IP」组合计数：只按邮箱可被用来锁死他人账号，只按 IP 会牵连 NAT 后的用户 |
| 改密踢下线 | JWT 内 `token_version` 声明与库中值比对，不一致直接 401 |
| 越权防护 | 所有查询限定当前用户；已用测试验证无法跨用户删除定期规则 |
| 分页上限 | `page ≥ 1`、`size / limit ≤ 200`，越界返回 1101 |
| SQL 注入 | 全参数化；此外对 LIKE 的 `%` `_` 做转义（参数化只防注入，不防通配符） |
| 日志脱敏 | 不打印密码、令牌、完整邮箱 |

## 五、工程化

| 项 | 实现 |
| --- | --- |
| 统一响应 | 业务错误 HTTP 200 + 非零 `code`；仅 401 / 403 / 404 / 500 使用非 2xx |
| 错误码 | 分段管理：11xx 参数、12xx 用户、13xx 科目、14xx 账目、15xx 预算、19xx 通用 |
| 数据库迁移 | Flyway V1–V5，V1 基线冻结，后续只增不改 |
| 持续集成 | GitHub Actions 14 步：起 MySQL → `mvn package` → 启动应用 → 7 套端到端 → 失败传日志 |
| 日志 | 按天 + 按大小滚动，保留 30 天；带 traceId；启动时打印日志目录绝对路径；级别可用 `APP_LOG_LEVEL` 调整 |
| API 文档 | springdoc 自动生成，`/swagger-ui/index.html` 可直接访问 49 个接口 |
| 数据备份 | `backup-db.ps1` 支持全量导出 / 仅结构导出 / SQLite 单文件快照 |
| 日志/缓存位置 | Maven 与 npm 缓存均在项目外（`D:\m2repo`、`D:\npm-cache`），项目目录可整体拷走 |

## 八、运行方式

```powershell
# 一键初始化（建库 + 迁移 + 前端构建 + 打包）
.\setup.ps1

# 启动
java -jar backend\target\personal-ledger-1.0.0-SNAPSHOT.jar

# 单元测试（115 项，无需数据库）
mvn -f backend\pom.xml test

# 端到端测试（377 项，需先启动应用）
Get-ChildItem backend\test-*.ps1 | ForEach-Object {
    powershell -ExecutionPolicy Bypass -File $_.FullName
}
```

- 访问地址：`http://127.0.0.1:8080/`
- API 文档：`http://127.0.0.1:8080/swagger-ui/index.html`
